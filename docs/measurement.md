# 测量口径


- **首字延迟**：发出原生 `turn/start` → 收到首个非空文字块；**首个可见事件**可先于正文，例如推理摘要。均包含客户端传输、排队和推理等待，不等于服务端 prefill。
- **总耗时**：请求发出 → 同轮 `turn/completed`，使用单调时钟；进程与临时会话准备单独记录。失败、超时和中断保留状态；失败不计入成功耗时分布，中断不计入失败比例。
- **估算输出速度 / 每 Token 耗时**：`(输出 Token - 推理 Token - 1) / (总耗时 - 首字延迟)`，时间换算为秒，后者取倒数。Token 来自同一轮原生用量，不用字符数或流式块数冒充。文字块可能含多个 Token，所以标为估算；少于 32 个可见 Token、少于两块、少于 200ms、缺分项、多消息、重试或路由变化时不提供估算。
- **端到端输出效率**：含推理输出 Token / 总秒数。另显示输入、输出、推理及缓存输入 Token，平均值、合计和输入缓存命中占比。无法观测服务端输入处理阶段，因此不提供伪“输入 Token/s”。
- **流式停顿**：文字块间隔 P50/P95/最大值、块数，以及可见重试和限流事件次数。块间隔不是逐 Token 延迟；原生接口未暴露的内部重试无法统计。
- **统计与趋势**：按来源、模型、provider、推理档位和固定任务分组，显示有效样本数、平均、P50、P95、最近记录和趋势。仅比较同上游声明、输入/输出 Token 的 2 次幂量级桶、缓存类别（零缓存、<50%、≥50%、未知）；近期 5 次 vs 此前 5–10 次，中位首字延迟增幅≥50%且≥500ms或估算速度降幅≥30%才提示。阈值为本工具的经验提示，未做统计显著性检验，不据此认定限速、质量下降或服务方意图。
- **标准测速**：`text-256-v1` 固定提示，目标为 256 个常见英文词（不是 256 Token，也不保证模型严格按词数输出）。每次手动触发 1 次逻辑请求，最长 90 秒，另有输入上下文与推理开销，沿用全局预算。原生短探针仍为原来的 OK 提示，无额外自动测速流量。切换页面、刷新和导出不推理。
- **实际会话**：原有文件观察器读取结构化 `task_started` / `task_complete` / `token_count` 等记录，累计用量增量避免重复事件累加。只保留有完整边界的轮次；无基线、压缩或累计值倒退时保留未知。轮次含工具和等待，不计算 TTFT 或模型解码速度，不扫描正文，不新增持续订阅或代理。
- **导出**：选择分组后点“导出数据”，JSON 写到运行数据目录的 `exports/`，显示完整路径。统计窗口为近 7 天且受原有各来源 80 条保留上限约束，明细最多 30 条；没有原始提示、回答、响应头或登录数据。桌面下载限制保持原样。
